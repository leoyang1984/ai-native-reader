# 平台状态与移植要求

本说明区分框架能力、代码编译和用户流程实际可用性。

## macOS

主要阅读主线已在 Apple Silicon Mac 验收：阅读、选文提问、连续追问、材料检索、确认保存、导出、重开恢复和书内引用回跳。使用的连接程序是 Codex CLI 0.160.0 与 pi 1.0.0。此记录不能替代其他 macOS 版本、CPU 架构或模型程序版本的验证。

尚未完整覆盖旧 Reflect 的所有桌面操作、Obsidian 外部链接跳转、较长对话分页和所有网络／账户异常组合。

## Windows 已知阻塞

- 本机桥接仅实现 Unix socket；Windows 分支直接返回错误，而桌面启动依赖桥接初始化，因此可能无法启动主界面。
- 需要支持 `.exe`、`.cmd` 和 Node 程序的正确发现与启动。
- 需要调整默认 MCP 数据路径、跨进程通道和目录权限检查。
- 需要配置 Windows 图标、安装包目标，并实际验证链接注册。

## Linux 已知阻塞

- 桥接默认使用 macOS 风格数据目录以及 `/private/tmp` 通道路径，需要统一为 Linux 可用位置。
- 需要实际验证 WebKitGTK 的 EPUB 显示、文字选择、双栏、键盘及深链接。
- 需要配置 Linux 安装包目标；不同发行版的依赖及兼容性需分别验证。

## 移植验收最低要求

每个平台都要实际走通：原创样书导入 → 阅读及布局切换 → 选文对话 → 停止／重连 → 人工笔记与测试 Vault 检索 → 确认保存 → 冲突导出 → 重开恢复 → 引用回跳。还要覆盖不含个人数据的独立目录、路径含中文、程序不存在、Vault 删除与断开，以及可选 MCP 接口。

完成后才应提供该平台的完整版下载。当前没有 Windows/Linux 完整版发行包。

## 浏览器

浏览器预览提供前端阅读体验及浏览器本地存储。不提供本机进程、桌面 SQLite、Vault 文件访问或本机 MCP；它不会自动读取桌面阅读数据。
